# R4 — البيانات والأمان
**الهدف:** تخزين سليم وآمن، وقفل دخول، ونسخ احتياطي حقيقي (الأقسام 5 و20 و21 و22).
**تملك:** مسارات R4 في `docs/TEAM.md`.
**المهام:**
1. SQLite عبر Drift **للكيانات الجديدة فقط** (ملاحظات، دفاتر، بطاقات، أسئلة، محاولات، مراجعات، مواضع التشغيل، جلسات القفل، سجل المزامنة، تنزيلات، مجلدات المكتبة)، مع معرّفات مستقرة والفصل بين معرف مودل والمحلي، وترحيل تدريجي من JSON. انشر العقد في `docs/contracts/R4.md` مبكراً.
2. فحص سلامة القاعدة والاستعادة عند الفساد، والكتابة بمعاملات، ونسخة قبل العمليات الحساسة، ورقم مخطط وترحيلات مختبرة.
3. قفل الدخول (القسم 5): BiometricPrompt مع PIN/نمط الجهاز، لا قفل إن لم يكن للهاتف قفل، إعادة القفل بعد 45 ثانية في الخلفية، لا إعادة قفل أثناء جلسة قفل دراسي. (يتطلب تغيير نوع MainActivity؛ اطلب من M.)
4. نسخ احتياطي إلى ملف يختاره المستخدم (Storage Access Framework) واستعادة منه، ونسخ تلقائي، بلا أسرار، وفحص الاستعادة باختبار حقيقي. (النسخ عبر الحافظة موجود.)
5. الخصوصية: معاينة ما يُرسل لمزود الذكاء الاصطناعي قبل الإرسال، تغطية حذف كل البيانات لما يُضاف من جداول، مفتاح الذكاء الاصطناعي في Keystore (مُنفَّذ).
**القبول:** اختبارات تكامل للقاعدة والترحيل والنسخ والاستعادة، وعدم فقدان بيانات حالية بعد التحديث.
